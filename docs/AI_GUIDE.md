# Как работать с AI-агентом над HydroGuard KG

Короткая инструкция для команды SuuTech: что уже настроено, что говорить агенту, как не потерять время.

## 1. Что настроено в репозитории
| Файл / папка | Зачем |
|---|---|
| `AGENTS.md` | Главная инструкция для агентов (стек, правила, команды). Codex, Cursor, Hoplite, Copilot читают её сами |
| `CLAUDE.md` | То же для Claude Code (импортирует `AGENTS.md`) |
| `docs/spec.md` | Полное ТЗ в markdown — агент читает нужные разделы |
| `docs/plan.md` | Срезы с чекбоксами, агент отмечает прогресс |
| `docs/decisions.md` | Журнал спорных решений |
| `.agents/skills/`, `.claude/skills/` | Скиллы: 7 проектных `hydroguard-*` + 11 официальных (Supabase, Vercel, Anthropic) |
| `.claude/agents/` | Субагенты `hydroguard-reviewer` и `hydroguard-debugger` |
| `.claude/commands/` | Команды `/slice`, `/review`, `/bug`, `/freeze-check` |
| `.mcp.json`, `.cursor/mcp.json` | MCP: Context7 (документация), Playwright (браузер), Supabase (только чтение) |
| `.claude/settings.json` | Запрет агенту читать `.env` и делать `supabase db push` |
| `skills-lock.json` | Версии внешних скиллов (`npx skills update -p` — обновить) |

Скиллы подключаются **автоматически**: агент видит их описания и загружает нужный, когда задача подходит.
Можно и явно: «используй скилл hydroguard-ai-scanner».

## 2. Первичная настройка (один раз, 10 минут)
1. Supabase MCP: в `.mcp.json` и `.cursor/mcp.json` допиши в URL `&project_ref=<ref твоего проекта>`
   (ref — в Supabase Dashboard → Project Settings). Затем в Claude Code `/mcp` → supabase → Authenticate.
2. Codex: MCP настраивается в `~/.codex/config.toml` (те же адреса), скиллы и `AGENTS.md` подхватываются из репозитория.
3. Скопируй `.env.example` → `.env.local` и заполни **только публичные** значения. Секреты — `npx supabase secrets set`.
4. Каждый, кто работает с агентом, читает этот файл и раздел «Безопасность» в `AGENTS.md`.

## 3. Золотые правила
1. **Одна задача = одна сессия (новый чат).** Длинный чат «тупеет». Срез закончен → новый чат.
2. **Сначала план, потом код.** Просишь план → читаешь → «ок» → агент пишет код.
3. **Маленькие шаги + коммит после каждого рабочего шага.** Сломалось — `git restore`, а не «почини всё».
4. **Проверяешь сам на телефоне.** «Сборка прошла» ≠ «работает». Жюри смотрит на телефон.
5. **Ревью отдельной сессией.** `/review` или новый чат: «проверь diff по ТЗ и безопасности».
6. **Баг — сначала причина.** Даёшь полный лог и шаги, просишь гипотезы, а не «пофикси».
7. **Ключи никогда не вставляешь в чат и код.**

## 4. Готовые промпты (копируй и меняй то, что в <>)

### Старт среза
```
Сделай срез <N> из docs/plan.md: <название>.
Сначала прочитай AGENTS.md, docs/plan.md и docs/spec.md §<раздел>, загрузи подходящие скиллы.
Дай план: какие файлы создашь/изменишь, какие миграции/функции, как я проверю на телефоне.
Код не пиши, пока я не скажу «ок».
```
(В Claude Code то же самое: `/slice срез <N>`.)

### После «ок»
```
Ок, делай. После каждого логического шага запускай npm run build && npm run lint && npm run test.
В конце: отметь docs/plan.md, сделай коммит, напиши «как проверить с телефона» по шагам.
```

### Ревью
```
Ты ревьюер. Проверь изменения этой ветки (git diff main...HEAD) по AGENTS.md и docs/spec.md:
безопасность (ключи, RLS, точные координаты), состояния loading/error/empty, zod, i18n, тесты.
Ответ: блокеры / важно / мелочи. Код не меняй.
```

### Баг
```
Баг: <что ожидал> → <что произошло>.
Шаги: 1) ... 2) ... Устройство/браузер: <Android Chrome / iPhone Safari PWA>.
Логи: <консоль браузера / Network / npx supabase functions logs <name>>.
Не исправляй сразу: дай 2–4 гипотезы, проверь каждую минимальной командой, покажи доказательство причины.
Потом минимальный фикс + регрессионный тест.
```
(В Claude Code: `/bug <описание>`.)

### Настройка AI-промпта на фото
```
Скилл hydroguard-ai-scanner. Вот результаты на 12 фото: <таблица фото → risk → confidence → правильно ли>.
Найди закономерность ошибок и предложи правку системного промпта. Не меняй контракт JSON.
```

### Дизайн экрана
```
Используй скиллы frontend-design и web-design-guidelines. Экран <название> для жителей села,
телефон 360 px, работа на улице: крупные кнопки ≥48 px, контраст, риск цветом+иконкой+текстом.
Сначала опиши 2 варианта визуального решения, я выберу.
```

### Проверка в браузере
```
Скилл webapp-testing. Напиши Playwright-тест: geolocation разрешена (координаты пилота),
загрузка тестового фото, мок ответа analyze-photo, отправка, метка на карте. Ещё один тест: офлайн → отчёт →
онлайн → одна запись на сервере.
```

### Готовность к демо
```
/freeze-check   (или: «Загрузи скилл hydroguard-demo-readiness и пройди чек-лист приёмки»)
```

### Слайды
```
Скилл pptx. Добавь в презентацию <файл> слайд «Демо MVP» со скриншотами из <папка> и QR на <ссылка>,
и слайд «Дорожная карта». Исправь опечатки из docs/spec.md §14.
```

## 5. Кто что просит у агента
- **Ринат (backend):** срезы 0 (Supabase), 1 (`analyze-photo`, промпт), 3–4 (погода, офлайн-синк, push).
  Скиллы: `hydroguard-backend`, `supabase`, `supabase-postgres-best-practices`, `hydroguard-ai-scanner`, `hydroguard-weather`, `hydroguard-web-push`.
- **Анархан (frontend):** экраны, карта, PWA-оболочка, i18n.
  Скиллы: `hydroguard-map-geo`, `hydroguard-offline-pwa`, `frontend-design`, `web-design-guidelines`, `vercel-react-best-practices`.
- **Мелике:** тексты рекомендаций, тестовые фото, проверка кыргызского (`TODO-ky`), слайды через `pptx`.
- Работаете параллельно → разные ветки (`feat/scanner`, `feat/map`), PR в `main`, ревью перед мержем.

## 6. Если агент «поплыл»
- Делает не то → остановить, `git restore .`, новый чат с более узкой задачей.
- Повторяет одну и ту же ошибку 2–3 раза → новый чат + `/bug` с полным логом.
- Придумывает API библиотеки → «проверь через Context7 актуальную документацию <библиотека> <версия>».
- Добавляет лишнее → «убери всё, чего нет в docs/spec.md».
- Ошибка может повториться → попроси дописать правило в `AGENTS.md` или нужный скилл.
