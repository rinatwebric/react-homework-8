# Готовность к демо SuuTech

Источник: `docs/spec.md` §4, §12, §13, §15, §16. Главное правило: **на сцене показываем только то, что стабильно работает.**

## Флаги
- `src/config/features.ts`:
  ```ts
  const flag = (v: string | undefined) => v === 'true';
  export const features = {
    weather: flag(import.meta.env.VITE_FF_WEATHER),
    sensors: flag(import.meta.env.VITE_FF_SENSORS),
    offline: flag(import.meta.env.VITE_FF_OFFLINE),
    push: flag(import.meta.env.VITE_FF_PUSH),
    farmer: flag(import.meta.env.VITE_FF_FARMER),
    premium: flag(import.meta.env.VITE_FF_PREMIUM),
    kyrgyz: flag(import.meta.env.VITE_FF_KYRGYZ),
    waterVolume: flag(import.meta.env.VITE_FF_WATER_VOLUME),
  } as const;
  ```
- P0 (сканер, гео, карта) — без флагов. Всё P1+ — за флагом, по умолчанию `false`; включается в Vercel env.
- Выключенная фича полностью исчезает из UI (не «скоро будет»), и её код не ломает сборку.

## Демо-данные (всегда подписаны)
- 10–15 отчётов с `is_demo = true` по району пилота — сид `supabase/seed.sql`. На карте бейдж «Демо».
- 3–4 виртуальных датчика с `is_simulated = true` (бейдж «Симуляция»), симулятор проверен в режиме `rise`.
- Погодный слой по всей стране — реальные данные Open-Meteo, обновлены перед выступлением.
- 3–4 проверенных фото со стабильной оценкой лежат на демо-телефоне в галерее.
- Заранее сделанный отчёт на карте — запасной вариант, если AI/сеть упадут.

## Заморозка (за 6–8 ч до защиты)
- Никаких новых фич и обновлений зависимостей. Только баги из чек-листа ниже.
- Тег релиза `git tag demo-v1`; Vercel production указывает на этот коммит. SW не должен обновиться во время демо.
- Пролистать карту района на обоих телефонах (прогрев кэша тайлов), установить PWA, разрешить гео и уведомления.
- Симулятор: `npm run simulate -- --mode reset` перед выступлением, ноутбук с запущенным `--mode rise` наготове.

## Чек-лист приёмки (`/freeze-check`)
- [ ] С телефона по ссылке: фото → оценка → подтверждение геопозиции → метка на карте.
- [ ] Отчёт без геопозиции отправить нельзя.
- [ ] В форме отчёта есть «вода в подвале» и «глубина воды в колодце».
- [ ] Авиарежим: отчёт сохраняется и после появления сети уходит сам, без дублей.
- [ ] Приложение открывается без сети и показывает кэшированную карту района.
- [ ] Карта показывает весь Кыргызстан с зонами риска по областям/районам.
- [ ] Симулятор отправляет показания, зона меняет уровень (норма → повышенный → высокий → критический).
- [ ] При высоком уровне уходят баннер и push, запись видна в `/admin` для служб.
- [ ] Push из `/admin` приходит на Android; на iPhone — при установленной PWA.
- [ ] Погодный баннер показывает данные по текущей геопозиции (осадки + влажность почвы).
- [ ] `/admin` доступен только модераторам; статусы меняются и видны на карте.
- [ ] Ключи API не видны в бандле и сетевых запросах (`grep` по `dist/`, вкладка Network).
- [ ] Везде (приложение, manifest, слайды) название SuuTech; симуляция и демо-данные подписаны.
- [ ] Android Chrome + iOS Safari; Lighthouse PWA/Performance ≥ 85 (мобильный профиль).
- [ ] Основной чанк ≤ ~200 КБ gzip; карта (с GeoJSON) и админка — отдельные чанки.
- [ ] Нигде нет белого экрана: без сети, с отказом гео, с битым ответом AI, без данных датчиков.
- [ ] Резервное видео демо записано; 3 репетиции питча проведены.

## Сценарий (90 с живого демо)
QR → PWA → скан заранее подготовленного фото → результат → «вода в подвале» → отчёт на карту → авиарежим →
второй отчёт → сеть → метка появилась → `/admin` → статус «в работе» → «Отправить предупреждение» → push на втором
телефоне → `npm run simulate -- --mode rise` → зона становится «высокий» → оповещение.
Ключевая фраза: «Сегодня о подземном подтоплении узнают слишком поздно. SuuTech превращает невидимую проблему
в измеряемые данные и предупреждает о риске заранее».

## Ответы жюри (честно)
- «Как вы узнаёте о подземной воде?» — три источника: жители, погода и влажность почвы, датчики; прямое измерение — датчики.
- «Это AI-прогноз?» — нет, пороговые правила; ML — после накопления данных пилота.
- «Вся страна?» — погодный слой и зоны по всей стране; отчёты и датчики там, где они появились.
